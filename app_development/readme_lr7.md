# Лабораторная работа 7: Кэширование с использованием Redis

## Описание задания

Реализовать кэширование данных в приложении с использованием Redis:

1. **Кэширование пользователей:**
   - Хранить данные о пользователе в кэше в течение 1 часа
   - При обновлении данных пользователя удалять данные из кэша

2. **Кэширование продуктов:**
   - Хранить данные о продукции в кэше в течение 10 минут
   - При обновлении данных обновлять данные в кэше

## Архитектура решения

### 1. Модуль Redis Cache (`app/redis_cache.py`)

Централизованный модуль для работы с Redis, реализующий паттерн Singleton:

```python
class RedisCache:
    def get(self, key: str) -> dict | None
    def set(self, key: str, value: dict, ttl: int) -> bool
    def delete(self, key: str) -> bool
    def clear_pattern(self, pattern: str) -> int
```

**Особенности:**
- Автоматическая сериализация/десериализация JSON
- Подключение через переменные окружения (`REDIS_HOST`, `REDIS_PORT`)
- Graceful handling ошибок подключения

### 2. Интеграция в репозитории

#### UserRepository (`app/repositories/user_repository.py`)

**Стратегия кэширования:** Cache-Aside с инвалидацией

- **Ключ кэша:** `user:{id}`
- **TTL:** 3600 секунд (1 час)
- **Операции:**
  - `get_by_id()` - проверка кэша → БД → сохранение в кэш
  - `update()` - обновление БД → удаление из кэша
  - `delete()` - удаление из БД → удаление из кэша

#### ProductRepository (`app/repositories/product_repository.py`)

**Стратегия кэширования:** Cache-Aside с обновлением

- **Ключ кэша:** `product:{id}`
- **TTL:** 600 секунд (10 минут)
- **Операции:**
  - `get_by_id()` - проверка кэша → БД → сохранение в кэш
  - `update_stock()` - обновление БД → обновление в кэше
  - `delete()` - удаление из БД → удаление из кэша

### 3. Docker Compose конфигурация

Redis добавлен как отдельный сервис:

```yaml
redis:
  image: redis:latest
  container_name: redis
  ports:
    - "6379:6379"
  volumes:
    - redis_data:/data
  networks:
    - app_net
```

## Выводы

### Преимущества кэширования с Redis:

1. **Производительность:** Значительное снижение нагрузки на БД
2. **Гибкость:** Различные стратегии кэширования для разных типов данных
3. **TTL:** Автоматическое истечение устаревших данных
4. **Масштабируемость:** Redis может работать в распределённом режиме

### Различия стратегий кэширования:

**Инвалидация (Users):**
- Удаляем данные из кэша при изменении
- Следующий запрос получит свежие данные из БД
- Подходит для часто изменяющихся данных

**Обновление (Products):**
- Обновляем данные в кэше сразу после изменения
- Следующий запрос получит данные из кэша без обращения к БД
- Подходит для данных, где важна скорость чтения

### Рекомендации по использованию:

1. Используйте кэширование для часто читаемых данных
2. Выбирайте стратегию инвалидации в зависимости от паттернов доступа
3. Устанавливайте адекватные TTL значения
4. Мониторьте hit rate (процент попаданий в кэш)
5. Реализуйте graceful degradation при недоступности Redis
